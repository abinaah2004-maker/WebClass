Accessibility Audit Report

Prepared by: Abinash Lamichhane

Purpose: A practical report template for reviewing the accessibility of my Web Programming coursework.

Important: This is a review worksheet, not a claim of formal WCAG conformance. Record the actual page, test method, evidence, and fix after carrying out each check.

Audit checklist

AreaWhat to checkResult to record
StructureMeaningful page title, one clear main heading, semantic landmarks, logical heading order.Not tested yet — inspect each page.
KeyboardAll links, buttons, and form controls work with Tab, Shift+Tab, Enter, and Space; focus is visible.Not tested yet — perform keyboard-only navigation.
FormsVisible labels, clear required fields, understandable errors, and instructions that do not rely only on color.Not tested yet — test valid and invalid submissions.
ImagesInformative images have useful alt text; decorative images have empty alt attributes.Not tested yet — review image purpose and alt text.
ContrastText and controls have sufficient contrast against their backgrounds.Not tested yet — measure contrast with a checker.
Responsive layoutContent remains usable at narrow widths and 200% zoom without unnecessary horizontal scrolling.Not tested yet — resize and zoom the browser.
Dynamic updatesLoading, success, and error messages are announced appropriately where needed.Not tested yet — inspect status regions and test with assistive technology.

Recommended testing sequence

  1. Choose a page and record its URL.
  2. Test keyboard navigation from top to bottom.
  3. Check labels, headings, image alternatives, and link text.
  4. Check contrast and responsive behavior.
  5. Record each issue with a reproducible step and expected result.
  6. Fix the issue, repeat the test, and update the result.

Conclusion

The checklist identifies what needs to be reviewed. A final conclusion should be written only after the pages have been tested and the results recorded.
