1. Problem and purpose

The Week 10 accessibility task focuses on keyboard access to the main content. A skip link should be the first keyboard stop, become visible when focused and allow a keyboard user to bypass repeated navigation. The destination must be a meaningful main-content landmark that can receive focus.

The repository already included skip links on the course homepage, Week 10 hub, portfolio and Book Search project. The Git exercise was updated to include the same basic keyboard-access pattern. This report records the implementation and source-level verification without claiming keyboard tests that have not been performed.

3. Keyboard test procedure

  1. Open a deployed page in the browser and reload it.
  2. Press Tab once. The “Skip to the main content” link should become visible and receive focus.
  3. Press Enter. The browser should navigate to the main landmark and the page's skip-link behavior should place focus on that target.
  4. Press Tab again. Focus should continue from the main content rather than traversing the navigation before it.
  5. Repeat on each page listed in the verification table.

Tab moves keyboard focus between controls. Enter activates the focused link. Tab does not activate a skip link by itself.
