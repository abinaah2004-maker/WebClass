FRIDAY / ERROR HANDLING

E2 — Test a 404 page.

A 404 response means the server could not find the requested resource. A helpful site should explain what happened and help visitors recover.

1. Open a route that does not exist

After the site is deployed, add a made-up path to its URL, such as:

https://abinaah2004-maker.github.io/WebClass/this-page-does-not-exist

2. Observe the response

Record what the browser displays. Check whether the page explains that the address is missing and whether it offers a link back to the homepage.

3. Compare after adding a custom page

Repeat the same test after the custom root 404.html has deployed. The custom page should be more useful than an unexplained error.

Evidence to capture: a screenshot of the missing route before and after the custom page is deployed. GitHub Pages may take a short time to publish the new file.
