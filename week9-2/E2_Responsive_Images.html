EXERCISE 02 · RESPONSIVE IMAGE FIX

Responsive Images

This page demonstrates resolution switching: the browser can choose a smaller or larger file of the same real photograph. The photograph below is a credited real-world image, not generated artwork. For the final submission, you can replace it with a photograph you take yourself and create your own optimized files.

1. Working responsive image

Resize the browser or open this page on a phone. The photograph stays the same, but srcset and sizes let the browser choose an appropriate JPEG file width. This is resolution switching; it does not crop the photo differently for mobile.

srcset: file candidatessizes: rendered width hintalt: text alternativewidth + height: layout stability

The browser will choose an image after it evaluates the viewport and device pixel ratio.

2. Understand the HTML

<picture>
  <!-- Art direction: portrait crop on small screens -->
  <source
    media="(max-width: 600px)"
    srcset="photo-480x640.jpg 480w,
            photo-720x960.jpg 720w"
    sizes="calc(100vw - 60px)">

  <!-- Landscape candidates for larger screens -->
  <img
    src="photo-960x640.jpg"
    srcset="photo-480x320.jpg 480w,
            photo-960x640.jpg 960w,
            photo-1440x960.jpg 1440w"
    sizes="(max-width: 980px) calc(100vw - 80px), 932px"
    alt="Describe what the photograph shows"
    width="960"
    height="640">
</picture>
  • picture: gives the browser alternative image sources.
  • source media: selects a portrait crop when the viewport is narrow.
  • srcset: lists image candidates with their intrinsic pixel widths.
  • sizes: tells the browser approximately how wide the image will appear in the layout.
  • img: is the required fallback and carries the alternative text.
  • width and height: reserve space and help prevent layout shifts.

3. Lazy loading images

Images lower down a long page can use loading="lazy", so the browser can wait until they are close to the viewport before downloading them. The main image at the top of this page is intentionally not lazy-loaded because it is visible immediately.

<img
  src="assets/gallery-photo-800.jpg"
  alt="Describe the actual subject in your photograph"
  width="800"
  height="533"
  loading="lazy"
  decoding="async">

Use lazy loading for below-the-fold images, not for the main image that appears immediately when the page opens.

4. Try it yourself

  1. Open this page on a laptop and note the selected image source.
  2. Make the browser window narrow or open the page on your phone.
  3. Press Inspect selected image again and compare the current source and rendered width.
  4. Open DevTools → Network → Img, reload the page, and inspect which image resource was downloaded.
  5. Try changing the sizes value and observe whether the browser chooses a different candidate.

Viewport information will appear here.

5. What to capture for evidence

  • A wide-screen screenshot showing the landscape image and this exercise page.
  • A narrow/mobile screenshot showing the portrait crop fitting the screen.
  • Optional: a DevTools Network screenshot showing the selected image resource and its dimensions.

6. Build your own local WebP and JPEG files

Sudip's version stores several optimized files in the project. The current live example above uses a real, credited Commons photograph at multiple JPEG widths. To make your version match the local-file comparison, download a photograph you are allowed to reuse and create these four exports with Squoosh:

  • assets/photo-400.jpg — 400 pixels wide, JPEG.
  • assets/photo-800.jpg — 800 pixels wide, JPEG.
  • assets/photo-400.webp — 400 pixels wide, WebP.
  • assets/photo-800.webp — 800 pixels wide, WebP.

In Squoosh, open the same source photograph, resize it to 400px and 800px wide while preserving its aspect ratio, then export each size once as JPEG and once as WebP. Save the four files in a folder named assets beside this exercise page. Check each exported file's byte size in File Explorer and write down the actual values; do not guess them.

<picture>
  <source type="image/webp"
    srcset="assets/photo-400.webp 400w,
            assets/photo-800.webp 800w"
    sizes="(max-width:650px) calc(100vw - 36px), 800px">
  <img
    src="assets/photo-800.jpg"
    srcset="assets/photo-400.jpg 400w,
            assets/photo-800.jpg 800w"
    sizes="(max-width:650px) calc(100vw - 36px), 800px"
    alt="Write an accurate description of your photograph"
    width="800" height="533">
</picture>

How to test: open DevTools → Network, filter by Img, reload the page, and inspect the downloaded filename. Repeat at a narrow and wide viewport. Then use the Inspect selected image button to read currentSrc and naturalWidth.

Do not claim WebP savings until the four local files exist and their real byte sizes have been measured.
