The largest time-based metric in the starter report is Largest Contentful Paint at 5.0 seconds. CLS is unitless, so it should not be compared with seconds or milliseconds.

Optimization explanation: The starter page downloads large remote images, does not reserve image dimensions, and loads an unused blocking jQuery dependency. The optimized version removes the unused library, uses smaller local images with explicit dimensions, and lazy-loads only lower-page gallery images. This is a combined exercise comparison, not proof that one change alone caused the full improvement.

Identify the bottleneck

Largest Contentful Paint is the slowest time-based metric in the sample starter run at 5.1 seconds. CLS is unitless, so it should not be compared with time values such as seconds or milliseconds.

What changed?

  • Reduced oversized image downloads and used appropriately sized assets.
  • Added width and height attributes so the browser can reserve layout space.
  • Deferred the application script so HTML parsing is not blocked.
  • Removed unused JavaScript and checked for long main-thread tasks.

These changes target image transfer, render blocking, and layout stability. A real audit is still needed to verify the effect on a specific website.

My audit checklist

  1. Open the page in Chrome DevTools.
  2. Select Lighthouse and choose the mobile profile.
  3. Run the audit and save the report.
  4. Fix the highest-impact issue first.
  5. Run the audit again with the same settings and compare the results.
